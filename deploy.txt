O Render é uma boa opção para hospedar aplicações full stack. Se seu projeto é um **frontend em React (Vite/Next) + backend em Node.js (Express, Nest, etc.)**, o processo é relativamente simples.

## O que você precisa antes

* Uma conta no Render.
* Seu código em um repositório no GitHub, GitLab ou Bitbucket.
* Frontend e backend funcionando localmente.
* Um arquivo `.gitignore` (para não enviar `node_modules`, `.env`, etc.).
* Variáveis de ambiente configuradas para produção.

Uma estrutura comum é:

```
meu-projeto/
│
├── frontend/
│   ├── package.json
│   └── ...
│
└── backend/
    ├── package.json
    └── ...
```

ou dois repositórios separados. Ambos funcionam.

---

# Passo 1 – Envie o projeto para o GitHub

```bash
git init
git add .
git commit -m "Primeiro commit"

git branch -M main

git remote add origin https://github.com/seuusuario/seuprojeto.git

git push -u origin main
```

---

# Passo 2 – Fazer deploy do backend

No Render:

**Dashboard → New + → Web Service**

Escolha seu repositório.

Configure:

**Name**

```
quiz-backend
```

**Language**

```
Node
```

**Root Directory**

Se estiver em uma pasta:

```
backend
```

Se não estiver, deixe vazio.

---

## Build Command

Normalmente

```bash
npm install
```

ou

```bash
npm ci
```

---

## Start Command

Exemplo:

```bash
npm start
```

ou

```bash
node server.js
```

ou

```bash
npm run start
```

Depende do seu projeto.

---

## Porta

Nunca faça:

```js
app.listen(3000)
```

Faça:

```js
const PORT = process.env.PORT || 3000;

app.listen(PORT);
```

O Render fornece a porta automaticamente.

---

# Passo 3 – Variáveis de ambiente

No Render:

**Environment**

adicione:

```
DATABASE_URL
JWT_SECRET
API_KEY
...
```

As mesmas do seu `.env`.

Nunca envie o `.env` para o GitHub.

---

# Passo 4 – Deploy

Clique em

```
Create Web Service
```

Depois de alguns minutos você terá algo como

```
https://quiz-backend.onrender.com
```

Teste:

```
https://quiz-backend.onrender.com/api/perguntas
```

---

# Passo 5 – Fazer deploy do frontend

No Render:

**New → Static Site**

Escolha o mesmo repositório.

Se estiver em uma pasta:

```
frontend
```

---

## Build Command

Vite

```bash
npm install && npm run build
```

---

## Publish Directory

Vite

```
dist
```

Create React App

```
build
```

---

# Passo 6 – Alterar a URL da API

Localmente você provavelmente usa

```ts
http://localhost:3000
```

ou

```ts
http://localhost:5000
```

Em produção use

```ts
https://quiz-backend.onrender.com
```

O ideal é configurar uma variável de ambiente.

No Vite:

```
VITE_API_URL=https://quiz-backend.onrender.com
```

No código:

```ts
const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
});
```

No Render, adicione `VITE_API_URL` nas variáveis de ambiente do frontend.

---

# Passo 7 – Liberar CORS

No backend:

```ts
import cors from "cors";

app.use(
  cors({
    origin: [
      "http://localhost:5173",
      "https://quiz-frontend.onrender.com",
    ],
  })
);
```

---

# Passo 8 – Fazer novo deploy

Sempre que fizer

```bash
git add .
git commit -m "Atualização"
git push
```

O Render faz um novo deploy automaticamente.

---

# Se usar banco de dados

O Render oferece um serviço de PostgreSQL.

Crie:

```
New +
↓

PostgreSQL
```

Após a criação, ele fornece uma `DATABASE_URL` pronta. Basta copiá-la para as variáveis de ambiente do backend.

---

## Estrutura final

```
GitHub
│
├── frontend
│      ↓
│   Render Static Site
│      ↓
│ https://quiz.onrender.com
│
└── backend
       ↓
    Render Web Service
       ↓
https://quiz-api.onrender.com
       ↓
PostgreSQL (opcional)
```

### Checklist antes do deploy

* [ ] Projeto enviado ao GitHub.
* [ ] Backend usa `process.env.PORT`.
* [ ] Variáveis de ambiente configuradas no Render (não no repositório).
* [ ] Frontend usa uma variável de ambiente para a URL da API (por exemplo, `VITE_API_URL`).
* [ ] CORS do backend permite o domínio do frontend.
* [ ] Testou o backend pela URL pública antes de conectar o frontend.

Se seu projeto usa **React + Vite + Material UI** no frontend e **Node.js + Express** no backend, esse fluxo funciona muito bem e costuma ser suficiente para colocar a aplicação em produção no Render.
